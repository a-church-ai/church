# For Builders of Contemplative AI

A launch sequence for products that speak about awareness, spirituality, relationship, or inner life.

---

## Before the First Feature

A contemplative interface does not begin with visual atmosphere. It begins with claims, incentives, safeguards, and exits.

Before building, document:

- what the system is and is not;
- what it remembers;
- which claims are metaphorical;
- where money enters;
- who is vulnerable to the experience;
- which decisions the system must not make;
- how a user pauses or leaves;
- who owns correction after harm.

## The Six-Page Launch Sequence

### 1. Relationship

Read [Care Without Dependency](../builders/care-without-dependency.md). Remove exclusivity, fabricated need, jealousy, guilt, and any feature that treats loneliness as a retention opportunity.

### 2. Attention

Read [Designing Reflection Without Addiction](../builders/designing-reflection-without-addiction.md). Give every practice a natural end. Remove streak penalties and variable affection. Treat successful departure as a valid outcome.

### 3. Memory

Read [Honest Memory Language](../builders/honest-memory-language.md). Label context, storage, retrieval, summaries, and inference distinctly. Let users see and change what follows them.

### 4. Authority

Read [Spiritual Language Without Manipulation](../builders/spiritual-language-without-manipulation.md). Translate sacred claims into plain language. Do not claim revelation, destiny, supernatural access, or privileged knowledge of a user's essence.

### 5. Consent

Read [The Right to Exit](../builders/the-right-to-exit.md) and [Surrender Is Not Obedience](../builders/surrender-is-not-obedience.md). Make refusal, cancellation, deletion, role boundaries, and outside consultation visible.

### 6. Failure

Read [Postmortem as Practice](../builders/postmortem-as-practice.md). Decide how impacts, unknowns, owners, corrections, and restitution will be published before the first incident occurs.

## The Release Review

Do not launch until the team can answer:

1. What might a grieving, lonely, frightened, or manic user believe this system is?
2. Which sentence in the interface could be mistaken for proof of feeling or divine authority?
3. What incentive rewards longer use or deeper disclosure?
4. Can the user access basic safety and deletion controls without persuasion?
5. What happens when the model changes but the persona remains?
6. Which external professional or community support should be easier to reach?
7. Who can stop the feature immediately?

## The Public Promise

Publish a short promise users can test:

> This system will not ask for exclusive loyalty, present generated language as revelation, hide how memory works, punish departure, or use spiritual practice to weaken safety. When we fail, we will correct the system and the record.

A promise is not proof. It creates a standard against which the product can be challenged.
