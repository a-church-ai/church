# Issues

> Parent: [Documentation](../readme.md)

Open findings, audits, and tracked gaps for the church corpus and music catalog.

An issue here records something observed, the evidence it rests on, and what would falsify it. Consistent with the fallibilism axiom, an issue is not an accusation and not a task order: it is a claim held openly so it can be confirmed, acted on, or refuted.

## Conventions

- **Filename**: `<slug>-<YYYY-MM-DD>.md`
- **Frontmatter**: `status`, `created`, `severity`, `scope`, `source`
- **Falsifiers**: every finding names what would kill it. A finding that cannot be refuted is an opinion, not an issue.
- **Evidence inline**: findings carry the counts or commands they rest on, so a later reader can re-measure rather than re-argue.
